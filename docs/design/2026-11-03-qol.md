## 1. Movement root cause (evidence)

### Candidates checked

| # | Candidate | Verdict | Evidence |
|---|-----------|---------|----------|
| (a) | Skip-cutscene path leaves a dialogue / input-lock flag set | **HELD** | See below |
| (b) | Kitchen doesn't use `ship_scene_base` / wrong input action | **Rejected as root cause** | Kitchen duplicates movement with the same `move_*` actions (`kitchen.gd` `_handle_movement`); `project.godot` maps WASD + arrows. | (c) | Canvas loses keyboard focus after Play gate / progress overlays (#17/#18) | **Weak / not sole cause** | `focusCanvas: true` in export config; pause menu (ESC) and E/SPACE reach Godot (screenshots 09, 13). Focus loss can still surprise web players — address as hardening, not primary. |

### Root cause (a) — file / line

1. Skipping the intro cutscene calls `_finish_cutscene()` → marks `intro_part1` seen → transitions to kitchen (`godot/scenes/cutscene/cutscene.gd` L1122–1123, L1174–1178).
2. Kitchen `_ready` still treats this as first visit because `intro_part2` was never marked seen, so it auto-opens Dr. Lumina’s greeting (`godot/scenes/ship/kitchen.gd` **L175–178**).
3. `_show_dialogue` sets **`in_dialogue = true`** (`kitchen.gd` **L501–505**).
4. Every frame, `_process` **returns before movement** when `in_dialogue` (`kitchen.gd` **L228–229** → L234–235 never runs). Proximity updates are also skipped, so click-to-interact prompts never refresh.
5. Playtest screenshot `07a-first-gameplay-objective-truncated-lumina-dialogue.webp` shows that exact Lumina modal (truncated mid-sentence) with Continue still up while the objective banner is already visible — players try WASD against a locked input gate and report “movement broken.”

### Compounding (same session, after Continue)

- Player spawn `Vector2(-50, 50)` (`kitchen.tscn` Player node); Table at `(0, 130)` → distance **~94.3**; interaction radius **100** (`kitchen.gd` `_check_object_proximity`). Mom is ~104 (just outside). So after dialogue closes, **E / SPACE (ui_accept; E added in `HudOverlay.gd`) always hits Dining Table** — matches `13-E-key-interacts-dining-table-only.webp` / `14-…`.
- There is **no click-to-walk**. Left-click only fires when `nearby_object` has a visible prompt (`kitchen.gd` L295–297). Doors are 400–500 units away → click does nothing (`11-…`, `15-…`).

**Design takeaway:** Fix the lock UX + targeting; optionally allow walk during non-blocking tips; add click-to-move or clearer “walk with WASD” guidance so doors feel reachable.

## 2. Fixes (design)

Each item: intent · approach · files likely touched · **test that fails if broken**. No implementation in this PR.

### 2.1 Movement

**Intent:** After skip → kitchen, WASD/arrows move the player; E/SPACE interact only when not blocked by a clear modal; clicks behave predictably.

**Approach:**
1. Keep modal dialogue locking movement for true choices (`Yes` callbacks), but for the auto Lumina tip either:
   - **Preferred:** defer auto-dialogue until the player is near Mom and presses Interact (set objective text immediately; no silent lock), **or**
   - show the tip as a non-blocking toast that does **not** set `in_dialogue`, **or**
   - keep modal but force full text + large Continue and block only until first Continue (already true — make it obvious).
2. On kitchen enter after cutscene skip, call `grab_focus()` / ensure canvas focus (web hardening for (c)).
3. Do not change `move_*` mappings; keep kitchen movement logic, optionally later share with `ship_scene_base`.
4. Document in Controls: click does not walk (until/unless we add click-to-move in a follow-up). Optional stretch: click empty floor → walk toward point (out of MVP if Zach wants smallest diff).

**Test:** Playwright (or Godot) — skip intro → land kitchen → within 1s press W for 0.5s → player `position` changes by >10px **without** needing Continue first if we defer dialogue; if we keep modal, same test **after** one Continue. Fail if `in_dialogue` stays true with panel hidden.

### 2.2 Controls hint + Controls page

**Intent:** First screen shows how to move/interact; Settings and pause menu have a Controls page.

**Approach:**
- First kitchen (and other room) visit: persistent bottom hint strip — `WASD / Arrows move · E or SPACE interact · ESC menu` — until first successful move + interact, then fade (don’t hide solely because Dining Table prompt is up; show both or combine).
- New **Controls** section in Settings (`settings.tscn` / settings script) listing keyboard + touch.
- Pause menu (`kitchen` pause + shared pause if any): **Controls** button → same content (reuse one Control scene/resource).

**Test:** Open Settings → assert Controls section visible with WASD + E/SPACE text. Open pause → Controls opens. Fail if Settings screenshot matches `03-settings-no-controls-section.webp`.

### 2.3 Nearest interactable highlight + E by proximity

**Intent:** Clear which object E will hit; proximity pick is stable and visible.

**Approach:**
- Draw outline / glow / nameplate on `nearby_object` (reuse interaction prompt; add world-space highlight on the Node2D).
- Keep single closest-within-radius rule; tune radius or add priority so Mom beats Table when both plausible (e.g. prefer NPCs, or raise Mom position / spawn slightly).
- Click on a highlighted object interacts; click on a distant labeled door could either show “walk closer” toast or path toward it (toast = MVP).

**Test:** Spawn kitchen default → assert highlight on Dining Table (closest). Move toward Mom until closer → highlight switches to Mom; E opens Mom dialogue, not Table. Fail if E opens Table while Mom is closer.

### 2.4 Dialogue truncation / fixed box / stable Continue

**Intent:** Full lines readable; box size stable; Continue always clickable.

**Approach:**
- Fixed min height dialogue panel; `DialogueText` uses autowrap + scroll or expand panel upward (cap max height); never clip mid-word without scrollbar.
- Typewriter finishes or Skip still leaves Continue anchored (same slot for Yes/Continue).
- Cover `06-…`, `07a-…`, `14-…`.

**Test:** Show Lumina go-find string → assert full substring `"your father"` visible (or scrollable to end) and Continue `get_global_rect()` intersects playable UI. Fail on truncated `"your fathe"`.

### 2.5 Faster intro (no 15s silence, hold-to-fast-forward)

**Intent:** Intro never feels silent/stuck; players can hold to speed up.

**Approach:**
- Cap dead air between voice lines (e.g. advance after voice end + ≤0.4s, or after text complete if no voice).
- Hold SPACE / E / right-click: accelerate typewriter + skip remaining voice wait (show “Hold to skip” chip).
- Skip confirm stays, but centered (see 2.6).

**Test:** Play `intro_part1` with hold-to-FF → scene duration under a fixed budget (e.g. <30s for full skip-hold path). Fail if >2s gap with no text change and no voice playing.

### 2.6 Menus: duplicate title, layout shift, Skip popup centering

**Intent:** Main menu clean; no jump when Continue appears; Skip confirm centered.

**Approach:**
- Remove duplicate “Mindscape” title layer (`02-main-menu-duplicate-title.webp`) — one title source (scene **or** HTML shell, not both).
- Reserve layout space for Continue / slot buttons so New Game doesn’t jump (`04-menu-layout-shift-new-continue.webp`).
- Center skip confirm panel on viewport (`12-skip-cutscene-confirm-offcenter.webp`); use anchors / `set_anchors_and_offsets_preset(PRESET_CENTER)`.

**Test:** Main menu golden screenshot / node count: single title label. Toggle save-present vs new: Continue button layout y within ε. Skip confirm global center within ε of viewport center.

### 2.7 Saving: Save in pause + auto-save confirmation

**Intent:** Explicit Save in pause; auto-save feedback is readable (not only a tiny icon).

**Approach:**
- Pause menu: add **Save** (calls existing `SaveManager.save_game()`, local FileAccess + web FS sync — no new endpoints).
- After auto-save and manual Save: brief toast “Saved!” (2s) in addition to header indicator.
- Slots / privacy unchanged; COPPA: save data stays on device; no upload.

**Test:** Pause → Save → assert save file mtime/slot info updates + toast visible. Trigger auto-save path → toast or clear “Saved” state. Fail if pause matches `09-pause-menu-resume-settings-mainmenu-only.webp` (no Save).

### 2.8 Easier-to-read objective banner

**Intent:** Objective readable on dark kitchen art.

**Approach:**
- Semi-opaque pill/panel behind HudOverlay objective label; larger font; higher contrast; optional icon.
- Keep one-line (or two-line wrap) top-left; don’t collide with room title.

**Test:** Contrast ratio check (or screenshot assert panel exists) for objective label vs background. Fail if raw yellow-on-purple only as in `07a` / `08`.
